1. INTRODUCTION                                          *devdocs-introduction*

devdocs.nvim downloads documentation from devdocs.io per language and
version, converts it once to markdown and reads it from disk. The symbol
under the cursor opens its page, examples are extracted from it, every
installed doc is searched with ripgrep, and a manager installs, updates and
removes docs. The README has the long version.

==============================================================================
2. COMMANDS                                                  *devdocs-commands*

                                                                     *:DevDocs*
:DevDocs {sub} [args]

  definition [text]      page/section of the symbol under the cursor, the
                         visual selection, or {text}
  example [text]         only the code examples of that entry
  open {doc} [entry]     open a doc by slug or name, optionally at an entry
  search [query]         grep the buffer's docs, then the newest version of
                         every other doc; "@css ..." narrows to one
  list                   the manager
  install [doc]          docs for the current buffer, or a named doc.
                         ! reinstalls
  install-all            every doc devdocs offers (asks; ! skips)
  uninstall {doc}        remove a doc (asks; ! skips)
  prune [lang]           delete old versions. Per language keep the newest
                         installed version that is enabled (the newest
                         installed one when all are disabled; versions
                         compare across the docs list and installed
                         meta.json, so an install newer than the list is
                         kept) and every installed version a project pins
                         in projects.json; delete the other installed
                         versions. Asks with the list, naming kept pinned
                         versions; ! skips. A language with one installed
                         version is never touched
  update [doc]           reinstall one doc, or every outdated one
  sync                   install what `import.docs` asks for
  status                 running install jobs
  detect                 what this buffer resolved to and why (root,
                         language, doc version and its source)
  resync                 forget what was detected for this project and
                         detect again. ! forgets every project
  recent                 recently viewed pages
  mirror [--force] [--scrape]
                         clone freeCodeCamp/devdocs, download every doc
                         through its container, install-all from that tree

Flat aliases:                                            *devdocs-aliases*
:DevDocsShowDefinition :DevDocsShowExample :DevDocsOpen :DevDocsSearch
:DevDocsList :DevDocsInstall :DevDocsInstallAll :DevDocsUninstall
:DevDocsUpdate :DevDocsPrune :DevDocsForceCloneAndScrape (= mirror --force)

3. SETUP AND OPTIONS                                            *devdocs-setup*

                                                             *devdocs.setup()*
require("devdocs").setup({opts})

  Optional. Every entry point resolves the defaults on first use. setup()
  registers the FileType hook for `install_as_needed` and the `import.docs`
  sync. Options, with defaults:

                                                        *devdocs-data_dir*
  data_dir            stdpath("data") .. "/devdocs"
                                                *devdocs-install_as_needed*
  install_as_needed   true | "prompt" | false. Install the docs a buffer's
                      language needs, in the project's version.
                                                          *devdocs-import*
  import.docs         {} docs to keep installed (slug, name, `*` globs,
                      case-insensitive). Empty: derived from Mason.
  import.recent_only  false  only the newest version of each doc
  import.import_only  false  the list is the whole allowlist
  import.all          false  every version; lookups switch per project
                                                         *devdocs-install*
  install.max_jobs    2 parallel jobs for install-all
  install.source      "tarball" | "json"
  install.tarball_url "https://downloads.devdocs.io/{slug}.tar.gz"
  install.doc_url     "https://documents.devdocs.io/{slug}/{file}"
  install.manifest_url "https://devdocs.io/docs.json"
  install.manifest_ttl 86400 seconds
  install.curl, install.tar   binaries
                                                          *devdocs-mirror*
  mirror.dir          nil = data_dir/mirror/devdocs
  mirror.repo, mirror.image, mirror.docker, mirror.git
                                                          *devdocs-search*
  search.rg           "rg"
  search.max_results  200
  search.prioritize_buffer_docs true
                                                            *devdocs-view*
  view.mode           "float" | "split" | "vsplit" | "tab"
  view.width, view.height   0.8 (fractions of the editor, or cells)
  view.border         nil follows 'winborder'
  view.wrap, view.conceal   true
                                                          *devdocs-lookup*
  lookup.fallback     "search" | "lsp_hover" | "none" when the symbol has
                      no doc entry
  lookup.scope        "buffer": only the buffer's docs when its language is
                      known, else the newest version of every doc.
                      "all": the buffer's docs, then every installed doc

A lookup's language comes from the filetype, then the file extension, the
shebang, then shell dotfiles (as $SHELL). Its version, for docs with several
installed versions, from an attached language server, the shebang, project
files (nearest package, then the git root), then the installed tool. Results
are cached per buffer and per project (projects.json, re-checked against the
files' mtimes once per session). See :DevDocs detect and :DevDocs resync.
                                                            *devdocs-list*
  list.release_dates  true: the manager dates each doc by when its version
                      was released upstream, from endoflife.date
                      (https://endoflife.date/api/v1/products/<product>,
                      cached 7 days in data_dir/releases/). false: no
                      network calls; every date is the DevDocs build date.
                      A date marked "≈" is the DevDocs build date (docs.json
                      mtime): no upstream release date is known for it.
                                                 *devdocs-extra_filetypes*
  extra_filetypes     filetype -> { doc bases }
  extra_mason         Mason package -> { doc bases }
                                                           *devdocs-hooks*
  hooks.on_install(slug), hooks.on_open(slug, path)
  notify              true

4. VIEWER KEYS                                                 *devdocs-viewer*

  q <Esc>     close                o   open on devdocs.io
  y           yank the url         <CR> follow the link under the cursor
  <BS> u      back                 e   only the examples
  p           paginated / whole    s   search inside this doc
              page
  ?           help
  n N         next / previous section
  c C         next / previous chapter

  A section is any heading (# to ######) outside code blocks. A chapter
  is a heading at the page's chapter level or above: the shallowest
  level that repeats after the page's first heading (its title), e.g.
  "# 3 - The Language" in the Lua manual, "## Syntax" on an MDN page.
  A count moves that many headings; the heading goes to the top of the
  window and the jump is on the jumplist (|''|, |CTRL-O|). In the examples
  view they step between examples. n and N do not repeat a search here:
  use /<CR> and ?<CR>.

  An entry that points into a page (Python, Lua, Rust, ...) opens
  paginated: one section at a time, starting at the entry. A page is a
  heading of any level, or a definition with an anchor (Python's
  `os.path.join()`), and its text up to the next one. A section with fewer
  than 5 non-blank lines under its title is shown together with the
  following section(s) until there are 5 or the doc ends. The title shows
  (3/12). An entry that is a whole page (most C++ and MDN entries) opens
  whole; `p` paginates it at the cursor. `p` toggles between the paginated
  view and the whole page, keeping your place; the footer shows what it
  switches to (`p pages` / `p paginated`). Paginated, n N c C turn to the
  page that holds the next heading, with the cursor on it at the top;
  turning pages is not on the history. `e` and `p` both go on the history,
  and `<BS>` puts the cursor back where it was in each view.

5. MANAGER KEYS                                               *devdocs-manager*

  j k gg G <C-d> <C-u> PgUp PgDn   move        } {    next / previous section
  <Tab> l h   expand versions      i   install     X   uninstall (asks)
  u U         update one / all     e   enable or disable
  <CR>        open in the viewer   o   open on devdocs.io
  /           live filter          s   sort by name / size
  r           refresh the list     A   install every doc (asks)
  m M         mark / clear marks   S :w  apply marks (install + uninstall)
  ?           help                 q   close

One row per language; ▸ expands it into its versions. On a language row, i
/ e / <CR> / o act on its installed current version (else the newest), u on
its outdated versions and X on every installed version the filter shows.
Columns: Version
("(current)" is DevDocs' rolling latest), Size (a language sums its installed
versions), Released (upstream release date, see |devdocs-list|; "≈" marks a
DevDocs build date used when none is known), Pages, Notes.

  Marking, applying and bulk delete (every delete asks once and lists what
  goes):
  m           mark / unmark, installed or not, move down (a language row:
              its installed versions the filter shows, else its newest
              version; expand it to mark an older one). Installing
              versions can not be marked.
  V v ... m   mark the visual selection (again: unmark)
  M           clear every mark
  :w  S       apply the marks: install the marked docs that are not
              installed, uninstall the marked installed ones. A centered
              menu lists "Install (N)" with the disk the downloads take
              ("-12.3 MB", DevDocsCost, red) and "Uninstall (N)" with the
              disk freed ("+45.6 MB", DevDocsFreed, green). At the bottom
              right, in normal text, "Disk used" and "Disk freed" (each
              left out when its group is empty) and "Net" = freed - used:
              "+33.3 MB" in DevDocsFreed (green) when space is gained,
              "-X MB" in DevDocsCost (red) when it is consumed, "0 B" when
              even. The menu also says how many marks the filter hides. y or <CR> applies, n q <Esc>
              cancels. Applied marks clear, failed ones stay. :wq and :x
              apply, then close the list (not when the menu is cancelled).
  V v ... X d uninstall the installed docs in the visual selection
  D           prune this language (the |:DevDocs| prune keep rule)
  gD          the same for every language (= :DevDocs prune)

  Marks survive filter changes; the status line shows "N marked" while any
  exist and the list buffer is 'modified', so :q refuses (E37) until they
  are applied or cleared; q and <Esc> close the list anyway.

  Marked mode: while any mark is pending the hint line shows
  "S apply 3 marked (2 install, 1 uninstall)  m toggle  M clear ..." and
  i, X, V ... X d and u do nothing (they would act on one row behind the
  plan's back); they say "N marked: S applies them (M clears)". D, gD, U
  and A still work.

6. DATA ON DISK                                                  *devdocs-data*

  data_dir/manifest.json          cached docs list
  data_dir/state.json             enabled docs, recent pages (version 1)
  data_dir/projects.json          detected languages/versions per project,
                                  tool versions (version 1; safe to delete)
  data_dir/docs/<slug>/meta.json  what is installed (version 1)
  data_dir/docs/<slug>/entries.tsv
  data_dir/docs/<slug>/anchors.json
  data_dir/docs/<slug>/pages/<path>.md
  data_dir/releases/<product>.json  endoflife.date release cycles (cache,
                                  safe to delete)
  data_dir/tmp/                   staging
  data_dir/mirror/                :DevDocs mirror clone

Deleting docs/<slug> equals :DevDocs uninstall. Files whose version is newer
than the plugin knows are never overwritten.

7. HIGHLIGHT GROUPS                                        *devdocs-highlights*

  DevDocsNormal NormalFloat        DevDocsBorder FloatBorder
  DevDocsTitle FloatTitle          DevDocsFooter Comment
  DevDocsHeader Title              DevDocsDim Comment
  DevDocsMatch Search              DevDocsInstalled DiagnosticOk
  DevDocsOutdated DiagnosticWarn   DevDocsError DiagnosticError
  DevDocsProgress DiagnosticInfo   DevDocsKey @type.builtin
  DevDocsLink Underlined           DevDocsMark DiagnosticHint
  DevDocsCost DiagnosticError      DevDocsFreed DiagnosticOk
  DevDocsHelpHeader bold

Key hints (manager hint line and help, viewer footer and help, apply menu)
draw keys in DevDocsKey and actions in DevDocsDim. DevDocsKey links to
@type.builtin: teal in NvChad's starlight theme, cyan in Neovim's default
scheme (Special is red in starlight). Help screens are tables: keys in
DevDocsKey, the column headers (Key / Action) in DevDocsHelpHeader (bold),
titles in DevDocsHeader. Override a group like any other: >lua
  vim.api.nvim_set_hl(0, "DevDocsKey", { fg = "#21BFC2" })
<

8. HEALTH                                                      *devdocs-health*

:checkhealth devdocs reports the Neovim version, which copy of the plugin is
loaded, tools, the data directory, installed docs, the docs list age, the
release dates cache and the install source.
